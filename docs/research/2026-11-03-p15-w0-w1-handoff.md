## 0. 一句话任务

把「持有标尺」从**个人计时器**改成**阶级标准**：`need` 不再乘 `buffer(classAge)`、
不再累加个体 `baselineSum`，改为以「上期各阶级人均收入 `refIncome[c]`」计价；
上升费用同批改用 `refIncome[c+1]`；"不被立刻弹回"改由 `graceDays` 只控判定计时。
目标是让 G-A（底层不再被抽空）与 G-B（形状能被参数拉开）通过，从而有资格进 W2 确认轮。

**不要做的事**：不要顺手优化聚类、不要改 G1.5 阈值、不要在同批加入位移准入（D-08）。
W0 的聚类优化必须与 W1 同批进入预注册，但两者是**独立提交**。

## 2. W0 管线硬化（先做，独立提交）

### W0-1 Ward 换 Lance–Williams 递推

- 文件：`src/runner/cluster.ts`。
- 现状：`wardCluster` 为朴素合并，每轮重算簇内 SSE，`O(n³)`；1680 点耗时 77 分钟。
- 目标：新增 `wardCluster` 的 `O(n²)` 实现（Lance–Williams 更新公式），
  朴素版**保留**为 `wardClusterReference` 供等价性测试使用，导出名不变。
- **验收口径必须写对**：两个数学等价的 Ward 实现在合并代价接近 1 ulp 时**会给出不同划分**
  （已实测：60 点 3 团数据，k=3 一致、k=4 时 ARI=0.948）。所以验收不是"与参考实现 ARI=1.0"，
  而是：
  1. 无并列数据集上 `ARI(新, 参考) = 1.0`（构造数据时刻意留出 >1e-6 的代价间隔）；
  2. 合并代价序列逐项相对误差 ≤ 1e-12；
  3. 1680 点 × k∈[2,5] 单次 < 60 s。
- 禁止：用新实现重跑并替换任何**已入库**产物；本轮之后的新产物才用新实现。

## 3. W1 rules-v6：需求参照系（A′）

### 3.1 公式（唯一权威定义，实现与文档必须逐字一致）

```text
# 上期宏观量，tick 开始时先算后用
refGain[c]      = mean{ gain_i(t-1) : i 存活且 class_i = c }         # 空阶级 → 保持上期值
refIncome[c](t) = (1-α)·refIncome[c](t-1) + α·refGain[c]

# 持有标尺：不再乘 buffer
need_i(t)       = refIncome[class_i](t) × bufferDays × ψ_eff[class_i]
                  ψ_eff = needMultiplier[c] × (env0[c]/env0[0])^φ     # φ=envExponent，与 v5 同

# 判定计时：只影响 belowNeedStreak，不影响 need
if classAge_i ≤ graceDays:  belowNeedStreak_i = 0（不累加）
else:                       belowNeedStreak_i += 1 if Value_i < threshold × need_i else 0

# 上升费用：改参照量为目的地阶级收入
ascendCost_i    = crossDays[c] × refIncome[c+1](t) × (1-discount) × openMultiplier
```

`referenceMode='own'` 时必须**逐位**等于 v5：

```text
need = classBuffer(classAge, bufferDays) × baselineSum × ψ_eff[c]
graceDays 按 0 处理（不读配置、不走分支）
ascendCost 用 dailyBase × E[c+1]（旧式）
```

### 3.2 尺度对齐（不要跳过这段去调参）

新 `need` 与 v5 在 `D = bufferDays` 处**结构同构但量级不等**：

```text
v5 :  need = bufferDays × B×E[c] × ψ[c]                    # 不含生产率
v6 :  need = bufferDays × refIncome[c] × ψ[c]
refIncome[c] ≈ B×E[c] × mean(ge × F(hard) × Opportunity)   # 含生产率，均值通常 0.5–1.0
```

即新标尺通常**略松**于 v5（同样的 `bufferDays`/`threshold` 下门槛低 0–50%）。
处理顺序（照做，别反过来）：

1. **先不改** `bufferDays`/`threshold`，按默认值跑 G-A，看实测 `P0`/`mUp`；
2. 若 `P0` 偏高（>0.5）导致结构塌成"全员底层"，**才**把 `bufferDays` 或 `threshold` 往上调，
   且在报告里记录为"尺度对齐"，不得写成"机制改进"；
3. 若 `P0` 仍接近 0，说明问题不在标尺严格度，按 §8 停止并回报，不要连续微调。

`deepEqual` 陷阱：`refIncome` 是浮点 EMA，`own` 模式必须**完全不读**该数组、也不更新其状态，
否则 G-D 的逐位一致会失败。

### 3.3 三个新参数（注册表 `src/core/params.ts`，缺一 `params.test.ts` 会失败）

| 注册名                    | unit            | domain                                          | affectsBehavior | wireTest（必须写进注册项）                                              |
| ------------------------- | --------------- | ----------------------------------------------- | --------------- | ----------------------------------------------------------------------- |
| `need.referenceMode`      | `dimensionless` | `{kind:'enum', values:['own','class']}`         | true            | 切换后 `need` 与 `ascendCost` 参照量改变，`'own'` 与 v5 golden 逐位一致 |
| `need.referenceSmoothing` | `dimensionless` | `{kind:'number', exclusiveMin:0, max:1}`        | true            | α 改大后 `refIncome` 更快跟随当期 `refGain`，`need` 方差增大            |
| `need.graceDays`          | `days`          | `{kind:'number', min:0, max:120, integer:true}` | true            | 改大后升阶者 `belowNeedStreak` 起算推迟，`mDown` 下降                   |

`bufferDays` 语义在两种模式下不同（`class`：持有天数；`own`：缓冲爬坡长度），
在该注册项的 `formulaRef` 里写清，不要新增 `need.needDays` 以避免两套语义并存。

### 3.4 状态变更（最容易漏，漏了 golden 与回放都会炸）

1. `SocietyState` 增加 `readonly refIncome: number[]`（长度 C，初值 `dailyBase × env0[c]`）。
2. `src/core/model/serialize.ts` 的 society 段加读写与校验（长度 = classCount，元素有限且 >0）；
   升 `STATE_SCHEMA_VERSION` 到 `stratify-state-v2`。
3. `refIncome` 的更新发生在**阶段 C 全部 gain 算完之后**（同一 tick 内先算后用为下一 tick 服务）；
   phase 顺序与快照语义不变。

## 6. 红线（违反任一条即视为未完成）

1. 不许用 `Math.random()`；新随机需求一律 `R(seed, tick, agentId, tag, counter)`。
2. `refIncome` 不得取同期值（`t` 而非 `t-1`），否则引入 agent 顺序依赖。
3. 不许在 `own` 模式下产生任何数值差异——G-D 是硬门禁。
4. 不许为了让 G-A 通过而调 `needMultiplier` 或 `threshold`；参数只许在 G-B 里扫，不许回填默认值。
5. 不许跳过 G-A/G-B 直接跑 `--stage full`。
6. 不许降低 0.70 的 ARI 阈值，也不许只报 max。
7. 不许把 `envExponent=0` 造出的封闭分层当作"结构自发涌现"的证据。
8. 业务常数必须走注册表（AGENTS 5），结算函数里不许出现裸字面量。
9. CI 不绿不得标记完成（AGENTS 10）。
