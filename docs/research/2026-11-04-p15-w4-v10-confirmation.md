## 3. 必须同报的限制

1. **只有两类，不是三类。** 分裂是 A（闭合 1:1 位移）vs B∪C（开放准入 + 占用锚定）。
   探索层 k=3 的轮廓仅 0.347 且 B 有点泄漏到 C；本轮 k 由轮廓选择为 2。
   `rule.md` 57 / P6-05 的「≥3 类」仍未满足。
2. **方向子项是 cell 均值口径。** 该口径沿用 W2 的「全部 cell」写法；C-w100 的
   cell 均值 P0=0.147，仅比门槛低 0.003。按运行级解读，C-w100 有 16/30 个 run 的
   P0>0.15（max 0.258），B-w15 与 C-w80 各有 1 个 run 的 mUp 略超 0.40；若按运行级
   解读，本轮方向子项不成立。因此「B/C 底轻」是中心趋势，不是逐 run 不变量。
   下一轮预注册必须写死方向预测的统计层级。
3. **类是体制级，不是涌现分叉。** 分裂主要由 `displacementShare` 决定
   （1:1 位移 vs 开放准入），`scarcityWeight` 只在第二类内部移动程度；
   没有证明迟滞/双稳态。
4. **G1.5 只是 go/no-go 闸门，不构成校准完成。** 不得据此声称默认参数已校准或
   结构已涌现，也不得把 A/B/C 的三个探索区域当作三类已确认结构。
5. **`clustering.g15.meanField` 仍是 v8 口径。** 产物中该子项报告 `met=false`
   （最差 cell P0=0、drift=0.315），不适用于 rules-v10；本轮判定使用预注册的
   `directional` 子项（cell 均值），两者在产物中分列，避免混读。
6. **最小簇门槛按 run 计。** 07 §8.1 的 `minClusterRuns` 以 run 为单位；同一 run 的
   w2b/w3 是两个特征点。从 `assignment` 重算：c0 为 30 run（60 点）、c1 为 150 run
   （300 点），最小 30 run ≥5，结论不变。已入库产物的 `clustering.minClusterMet`
   由按点数比较的旧脚本生成（60≥5）；脚本已改为 `minClusterRunCount`，后续运行使用
   按 run 计的新口径。
