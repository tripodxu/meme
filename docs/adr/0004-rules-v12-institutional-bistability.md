# 0004 rules-v12 显式制度双稳态

- 状态：accepted（2026-11-05 按目标授权落地；方案 A，`θH` 默认 0）
- 日期：2026-11-05
- 决策者：徐鼎（提案人；按 2026-11-05 执行目标确认）
- 相关任务：P6-05c（P6-05/P6-05b 失败后的规则修订与重跑）
- 取代/被取代：无

## 背景

P6-05 用 07 §8.1 的 11 维全特征（P0..P4、G、top10、Mup、Mdown、S、O）对 6 个
参数区域 × 30 个新 seed × 10950 tick 做 k=3 聚类，未通过：簇 [30,118,32]，
ARI median 0.491、silhouette 0.344、14600 同簇率 0.667（changes/0057）。
A（share=1）与其余五个区域分得很开（k=2 silhouette 0.649），但第三簇只存在于
非 A 体制内部，沿 S/O 轴把非 A 分成“高隔离低开放”和“低隔离高开放”两半；
它不稳定，是慢变量的相位漂移，不是第三个吸引子。

P6-05b 进一步检验两个机制假设：提高 `openness.segregationWeight` θS（4/8/12）
与启用 `ascent.occupancyMemoryDays` H（0/180），6 cell × 30 新 seed × 10950 tick。
结果更差：k=3 簇 [136,17,27]，三簇都混合全部 6 个 cell；ARI 0.291、
silhouette 0.297、14600 同簇率 0.550，H1/H2 均不成立（changes/0058）。
按预注册决策规则，停止在同一规则上继续调参。

规则 45 已经写下“高流动 → 高开放 → 低跨越成本/多跨层关系 → 更高流动”与
“高隔离/高不平等 → 低开放 → 高跨越成本/少跨层关系 → 更低流动”的候选双稳态
机制，但当前实现只有一个慢平衡点：

`O_target = sigmoid(θ0 + θM(Mup−Mref) − θG(G−Gref) − θS(S−Sref))`

`O` 以 τO 平滑跟随 `O_target`，没有自反馈/迟滞；S 或 Mup 的小幅变化只会让 O
平滑移动，不能把它锁定在两个稳定区间。网络重构也很弱（rewireProb=0.05），
不足以单独维持第二个状态。P6-04a 的消融显示，在已测机制中网络/制度轴最可能
承载第三类（β=0 的次要指标 ΔG −0.0596、ΔMup +0.1382）；P6-04b 的
`survival_hint` 又在同一 S/O 轴上产生过强分离（Mup→0、S→0.354、O→0.143），
说明这条轴有能力承载一个不同状态，但当前规则没有把它锁住。

## 决策

在 rules-v12 中给开放度目标加入**显式自反馈（迟滞）项**，使 O 在参数区间内
出现两个稳定不动点；默认关闭，`θH=0` 与 rules-v11 逐位一致。

具体规则：

1. 新参数 `openness.selfReinforcement`（θH），默认 `0`，域 `[0,20]`，
   单位与 θ0/θM/θS 同为 sigmoid 斜率单位；必须进入参数注册表、
   `configHash`/`paramsHash` 与 golden 向量。
2. 目标值改为：

   `O_target = sigmoid(θ0 + θM(Mup−Mref) − θG(G−Gref) − θS(S−Sref) + θH×(O_prev−0.5))`

   其中 `O_prev` 是本 tick 更新前的 O（tick 期初值），不得使用同期更新后的 O，
   不得引入个体顺序依赖。`O` 仍按 rule 43 的慢更新跟随 `O_target`，
   并 clamp 到 `[0,1]`。

3. `θH=0` 时必须与 rules-v11 的 O 轨迹逐位一致；`θH>0` 时允许两个稳定不动点
   （低开放/高开放），由 θH 与 θM/θS/θG 的联合取值决定是否存在。
4. 失败行为：θH 超出域、非有限值或配置校验失败时拒绝启动；不得静默钳制为
   默认值。`openness.updateMode=fixed` 时 θH 不生效。
5. 由核心引擎执行；Jev 不参与 O 的计算，也不因 θH 改变合法行动集合。

选择自反馈而不是新增制度状态的理由：O 已经是权威状态，改动只在目标函数；
不需要新状态字段、快照迁移或回放语义变化；默认 0 可保持旧行为，便于消融。

## 备选方案

| 方案                    | 优点                                                    | 代价                                                                     | 未采用原因                       |
| ----------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------ | -------------------------------- |
| A 自反馈/迟滞（本 ADR） | 改动最小；O 已是状态；默认 0 保持 v11；直接检验 rule 45 | 需要新参数、config schema 升版、golden 重算；可能只得到 O 双峰而非第三类 | —（采用）                        |
| B 显式制度状态机        | 双稳态最强、可解释                                      | 新权威状态字段、state schema 升版、快照/回放/迁移成本高                  | 先试最小改动；A 失败再单独立 ADR |
| C 网络重构锁定          | 不改状态                                                | P6-05b 显示 θS/网络轴弱；可能只延迟不锁定                                | 证据不足，优先级低               |
| D 制度捕获/精英闭锁     | 可能产生真实第三态                                      | 新增行为/行动与 Jev 语义，范围过大                                       | 超出本轮最小修订                 |

## 后果

- 正面：把 rule 45 的候选双稳态从散文变成可检验的机制；默认关闭，旧行为和
  旧实验可复现；P6-05c 可用同一套全特征 k=3 判据直接检验。
- 负面/限制：θH 可能制造人为双峰而不产生第三类阶级结构；参数区间需要校准，
  存在过拟合风险；config schema 与 golden 哈希会变；P6-05c 仍需新种子集，
  不能复用 P6-05/P6-05b 的 seed。
- 需要新增或修改的测试：θH 域/接线/进 configHash；θH=0 与 v11 逐位一致；
  固定点/双稳态单元测试（存在两个稳定 O 的解析或数值判据）；τO 与
  updateMode=fixed 的交互；确定性/快照回放；golden config/params 向量。
- 需要同步的文档与版本字段：`rule.md` 规则 42/45（v12）、`docs/03`（O 更新）、
  `docs/07`（P6-05c 预注册）、`docs/01`、`AGENTS.md`、参数注册表、
  `CONFIG_SCHEMA_VERSION` v6→v7（新增字段）、`rulesVersion` rules-v11→v12；
  若行为变化需要，`engineVersion` 同升。状态 schema 不变（O 已在状态中）。

## 兼容性

- 旧 run/artifact 仍可按其保存的 config 读取与重放；但 rules-v12 的
  `configHash/paramsHash` 会因新字段与规则版本变化而不同，**不得跨版本比较
  哈希或把旧 artifact 当作 v12 证据**。
- 旧 manifest 在 v12 下重跑必须显式迁移 config（θH 默认 0），并新建
  experimentId；不得覆盖旧实验。
- Jev 决策协议、行动集合和状态 schema 不变；Jev 侧不需要迁移。
- 默认 θH=0 时结算逐位一致，但 rulesVersion 仍按行为变更规则升为 v12，
  以免“默认相同”掩盖规则版本差异。

## 验证

待验证（本 ADR 为 proposed，尚未改规则）。计划证据：

1. 参数接线与域测试、θH=0 逐位一致测试、双稳态固定点单元测试、golden 向量；
2. P6-05c 预注册：θH∈{0,6,10,14} × 固定 share=0.5/w=15 或更宽区域，
   30 个全新 seed × 10950 tick + 60 个 14600，全特征 k=3，沿用 P6-05 验收；
3. 若 P6-05c 仍无稳定第三簇，A 方案判失败；按新 ADR 讨论 B（显式制度状态机），
   不得继续调 θH 或换 seed。

## 结果（2026-11-06）

P6-05c 已按预注册执行（`p6-05c-f7f3cc91`，160/160、0 排除、0 灭绝）：
k=3 簇 **[72, 39, 9]**、silhouette **0.215**、ARI median **0.182**、
14600 同簇率 **0.675**，三项均未过线；k=2 诊断 [111, 9]、silhouette 0.505，

θH 自反馈没有产生稳定第三簇。按本 ADR 与 changes/0061 的预注册，
停止调 θH/换 seed/换 k，转入 **B 方案（显式制度状态机）**；
B 方案须另立 ADR、rules-v13 与全新预注册，不能用本轮结果充当其证据。
